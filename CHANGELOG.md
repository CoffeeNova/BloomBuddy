# BloomBuddy Changelog

## [Unreleased]

### Added

- **OmniCC coexistence (round-3 feedback, 2026-08-15):** the overlay's `Cooldown` widget sets `noCooldownCount = true` — the official opt-out for countdown add-ons. On the tester's client OmniCC is installed and drew its own numbers on the swipe (looked like a stuck digital countdown that `/bb timer` could not hide); the flag makes OmniCC skip the widget entirely.
- **`/bb debug` now also dumps overlay state:** for every tracked compact frame — overlay shown/rect, cooldown widget shown + `GetCooldownTimes`, stacks/timer text + anchors, and the raw aura fields (spellId, remaining, duration, applications) behind the display. In-game ground truth for the pending placement/swipe acceptance.
- **Cooldown swipe as the default remaining-time display (user feedback, 2026-08-15):** the overlay now uses a native `Cooldown` widget (`CooldownFrame_Set(expirationTime - duration, duration)`) that the client animates as a darkening clockwise sweep — smooth, no Lua timer. Configured `SetSwipeColor(0,0,0)`, `SetDrawEdge(false)`, `SetDrawBling(false)`, `SetHideCountdownNumbers(true)`.
- **Digital countdown is now opt-in:** new setting `showTimer` (default `false`) + `/bb timer` slash command to toggle it. `/bb` status now reports it.
- **Stacks fix:** stack count is read from `aura.applications or aura.charges` — `.count` is NOT the field on this client (verified: BigDebuffs, BetterBlizzFrames, ArenaAnalytics). The stacks text was previously always blank.
- **In-game verification (2026-08-15, user):** `CompactUnitFrame_UpdateBuff` = `nil`, `CompactUnitFrame_UpdateAll` = `function`, `CompactPartyFrameMember1` is a real frame with `unit="player"` and `displayedUnit` populated; Lifebloom spell ID `33763` (R1) confirmed via `GetSpellInfo`; show/hide works per member and per aura, `/bb enable`/`/bb disable` lifecycle works; `aura.applications` returns the stack count. `CompactRaidFrame1` is `nil` outside a raid (expected).
- **Project scaffold** (v0.1 phase 0): `BloomBuddy.toc` (Interface 20506), `bootstrap.lua` (global `BB` table, event frame, `ADDON_LOADED` init), `Data/` (Constants, DefaultSettings, Localization), `Utils/` (Tables, Timers), `Classes/` (Events, Settings, Frames, OptionsUI).
- **AI development library** (`.github/`): agent instructions, context/architecture, agents, skills, prompt templates, PowerShell tools, development plan.
- **Slash commands**: `/bb` (status), `/bb enable`, `/bb disable`, `/bb timer`, `/bb debug`, `/bb help`.
- **Settings** (`BloomBuddyDB`): `enabled`, `scale` (default 1.5), `party`, `raid`, `showTimer` (default false).
- **Static analysis**: the **luahelper MCP** server as the repo's Lua lint gate — see `.github/CONTEXT.md` and `AGENTS.md`.

### Changed

- **`Classes/Frames.lua`:** removed the per-tick `compact scan` debugPrint (it flooded chat every 0.5 s while `/bb debug` was on and scrolled the overlay dump away); `Frames:dumpOverlays()` now prints a header first and pcall-guards each frame's section, and reports the overlay rect vs the frame rect plus the stacks/timer fontstring rects (round-4 feedback: stacks still read as "bottom-center" and the swipe still wasn't visible — geometry dump was being drowned by the spam).
- **Swipe direction fixed (round-5 feedback, 2026-08-15):** the overlay's `Cooldown` widget now sets `SetReverse(true)` — the client-correct sweep direction on this client (every working addon — BigDebuffs, SweepyBoop, ClassicAuraDurations, BetterBlizzFrames — sets it). The default swept the wrong way: the icon lightened instead of darkening. Also `SetDrawSwipe(true)` explicitly.
- **Swipe rendered invisible without the cooldown template (round-4 feedback, 2026-08-15):** the overlay's `Cooldown` widget is now created with `CreateFrame("Cooldown", nil, child, "CooldownFrameTemplate")` plus `SetAlpha(1)` and `SetSwipeColor(0,0,0,0.7)` (BigDebuffs' exact setup). Every working addon on this client (BigDebuffs, ClassicAuraDurations, SweepyBoop) creates cooldowns with that template — a bare `CreateFrame("Cooldown")` has no swipe texture, so the sweep ran (`/bb debug`: `sweep=Y, dur=7000`) but rendered nothing. The `/bb debug` dump (overlay rect vs frame, stacks/timer rects, cooldown `GetCooldownTimes`) confirmed the geometry and the root cause.
- **Overlay moved to the top-right of the member frame + stacks to the icon's top-left (user feedback, 2026-08-15):** `OVERLAY_ANCHOR` is now `TOPRIGHT` (offset -2,-2) — the native buff/debuff strip runs along the bottom of the frame, so the previous right-edge (vertically centered) icon had its lower part covered by debuffs; the upper-right area is clear (SweepyBoop's proven compact-frame placement). `OVERLAY_STACKS_ANCHOR` is now `TOPLEFT` (offset 2,-1) — user request; bonus: the clockwise swipe covers the top-left of the icon last, so the number stays readable.
- **`Classes/Frames.lua`:** the overlay's `Cooldown` widget opts out of countdown add-ons (`noCooldownCount = true`); the overlay is shown before the cooldown is driven so the C-side sweep initializes while visible; added `Frames:dumpOverlays()` (the `/bb debug` diagnostic).
- **`Classes/Frames.lua`:** the overlay carries a native `Cooldown` swipe + `stacks` FontString (`aura.applications`) + optional `timer` FontString (gated by `showTimer`); detection returns the aura object (`Frames:getLifebloomAura`) — `isLifebloomAura` is a thin wrapper; `updateOverlay`/`hideOverlay` centralize show/hide + `CooldownFrame_Clear`.
- **Core feature redesigned (client research, 2026-08):** on TBC Anniversary 2.5.6 the native buff icons on compact frames (raid + raid-style party) are **C-rendered** — they cannot be resized or hidden per-buff. The core now draws a **custom enlarged Lifebloom overlay icon** on compact frames (the pattern proven by SweepyBoop/BigDebuffs on this client) instead of `SetSize` on a native icon.
- **`Classes/Frames.lua` rewritten:** tracks compact frames via the `CompactUnitFrame_UpdateAll` hook (the real hook point on 2.5.6 — `CompactUnitFrame_UpdateBuff` does not exist), reads `frame.displayedUnit or frame.unit`, shows/hides an overlay icon (base 20 px × scale, anchored bottom-left, tunable), refreshed by the hook + `UNIT_AURA` / `GROUP_ROSTER_UPDATE` + a 0.5 s safety ticker.
- **Ticker lifecycle fixed:** `/bb enable` now starts the safety ticker and `/bb disable` stops it and hides overlays (previously the ticker was only started at load, so enable-after-load never ran).
- **`Data/Constants.lua`:** added `MAX_AURA_SCAN`, `OVERLAY_BASE_SIZE`, `OVERLAY_ANCHOR` / offsets / frame level, `SHOW_TIMER`/`SHOW_STACKS` + text anchors/sizes; removed the unused `MAX_PARTY_BUFFS` / `MAX_RAID_BUFFS`.
- **Docs:** `README.md`, `.github/CONTEXT.md`, `.github/ARCHITECTURE.md`, the `unit-frame-buffs` and `wow-api-20506` skills, and the development plan updated to the overlay design, the swipe + opt-in timer, the `.applications` stack field, the OmniCC opt-out, and the verified client facts.
